# V44 full-PREP physical boundary manifest

Status: preregistered experiment contract, before wrapper implementation and
before the canonical physical run.

Production baseline: V44 PREP5 at
`e16f27ff14098a946fc354929cb6057af1ff0189`.  The production files under
`rtl/**` remain byte-locked by `audit/production_rtl_v44_prep5.sha256`.

## Scientific question

The experiment compares V36 PREP5 with V43 PREP5 after integrating the real
predictor, generated ROM contents, polynomial/CSA predictor, signed cut,
`Carry_Low`, both product paths, all five correction branches and the exact
selector.  It asks whether the isolated-kernel V43 ranking survives this
integration.  It is not a minimum-period search and cannot establish complete
divider or signoff Fmax.

## Exact measured boundary

One experiment-only, parameterized wrapper will instantiate the unmodified
production `hz_prep` module.  The synthesis top name, ports and output register
structure will be identical for both parameter values; the only intended
change is `VARIANT=36` versus `VARIANT=43` inside `hz_prep`.

The primary ports are:

- `Clk` and active-low asynchronous `Reset_N`;
- 64-bit `Divisor` (`D`);
- 64-bit `Dividend_Hi` (`X`);
- registered 96-bit selected `NX`;
- registered 64-bit selected reciprocal remainder `r`.

The output boundary therefore contains 160 data flops.  It intentionally does
not add a registered correction-index output, because extra selector fanout
would perturb the data path being compared.  The index remains observable in
functional simulation through the production PREP instance.

The measured combinational cone contains all of the following:

1. the real bucket calculation from `D`;
2. the real coefficient, square and cube ROM reads;
3. the polynomial and signed predictor CSA tree;
4. `Pred_S`, `Pred_C` and `Pred_Wrap`;
5. the production signed cut at bit 46;
6. the real low-part addition and `Carry_Low`;
7. both architecture-specific products, `(pD)` and `(pX)`;
8. five residual branches for `p` through `p+4`;
9. five `NX` branches for `pX` through `(p+4)X`;
10. the exact PREP5 sign-based selector;
11. the production `D=2^63` special mux;
12. identical asynchronous-reset output registers.

There is no external `Candidate_K`, no external predictor state and no
single-candidate shortcut.  The old `hz_kernel_core` boundary is not reused.

`FINAL`, the divider transaction protocol, error gating and the Stage-1
pass-through copies of `X` and `D` are outside this first boundary.  Those are
common downstream/control structures rather than PREP arithmetic.  Their
exclusion must remain explicit: this result is for the tested full-PREP cone,
not the complete divider.  A later full-PREP-plus-current-FINAL experiment is
permitted only after this integration checkpoint is understood.

## Legal arithmetic and the power boundary

Functional comparison uses the production legal domain
`2^63 <= D < 2^64` and `0 <= X < D`.  The wrapper does not constrain or assume
`D > 2^63` during synthesis.  The existing `D=2^63` path remains present and
must produce

```
n = 2^33
r = 0
NX = n*X.
```

Both variants receive exactly the same input domain and special-path logic.

## ROM representation

The experiment uses `scripts/gen_roms.py` and the production
`hz_predictor_roms` `$readmemh` arrays:

| table | words x bits | content bits |
|---|---:|---:|
| coefficient | 64 x 167 | 10,688 |
| square A | 256 x 16 | 4,096 |
| square B | 32 x 10 | 320 |
| cube | 256 x 24 | 6,144 |
| total | | 21,248 |

The four generated files must match `audit/rom_v44.sha256` before simulation
and synthesis.  In this Nangate45 standard-cell flow the arrays are explicitly
expanded by Yosys into combinational logic/mux structures and then mapped to
ordinary library cells.  There is no SRAM macro, black box, zero-delay oracle
or area-free coefficient input.  The mapped report must record zero residual
memories, cell-type distribution, ROM-related mux structure/fanout where it
can be recovered, and whether a ROM/predictor source cone is critical.

The representation and generated bytes are identical for V36 and V43.  The
ROM cannot be excluded after results are known.

## Cancelled full-top precedent and mapping policy

Run `33961763954` is diagnostic evidence, not a physical result.  It expanded
the common ROM and full divider successfully, leaving zero memories, but then
started a second whole-design ABC pass with a 1 ns delay target.  At the start
of that redundant pass the flat networks contained:

| variant | generic cells after the first ABC | gates passed to second ABC |
|---|---:|---:|
| V36 | 194,382 | 194,378 |
| V39 | 195,601 | 195,597 |
| V43 | 155,756 | 155,752 |

The three second ABC processes were still running about 22–23 minutes later
when the workflow was cancelled.  This does not show that ROM expansion is
impossible; it shows that the previous double-ABC, 1 ns full-top command was a
wasteful checkpoint architecture.

The new flow will perform one standard-cell mapping pass after a no-ABC Yosys
lowering step.  Both variants use the same command, Nangate45 Liberty and delay
constraint.  Any mapping timeout or memory failure is an infrastructure/
feasibility outcome, not an architecture timing failure.

## Single timing point

The canonical integration checkpoint is preregistered at **15.0 ns**.  This is
one common, deliberately conservative period, not a grid point inferred from
historical 10 ns slack, PREP6 Tmin or a selected seed.  The old cancelled run
shows that the full boundary is a roughly 156k–194k-cell generic logic problem
before standard-cell remapping, with a long common ROM/predictor cone in front
of the product and selector.  A 15 ns target is intended to provide closure
headroom while still enabling timing-driven mapping, placement and repair.

There will be no automatic second period.  If this point proves unsuitable,
the run remains canonical diagnostic evidence and the reason is documented
before any new experiment is proposed.  No Tmin or Fmax is derived from it.

## Common physical contract

The two canonical jobs will use the same:

- generated ROM bytes and production RTL source hashes;
- Yosys/ABC invocation and Nangate45 typical Liberty;
- pinned ORFS source/platform commit
  `0c914a7471340da86058dfe4d25d537f0282a508`;
- pinned official image recorded by `physical/image.txt`;
- clock period 15.0 ns;
- input transition 0.05 ns, output load 5 fF, max transition 0.20 ns and
  max fanout 20;
- zero external I/O delay and reset false path;
- placement density and one identical absolute floorplan;
- post-CTS `repair_timing` enabled and `LEC_CHECK=0` only for the documented
  Kepler AVX-512 limitation;
- mapped import, floorplan, placement, CTS, post-CTS repair, global route,
  detailed route, OpenRCX, extracted final STA and final artifact generation.

The old 520 x 520 die / 500 x 500 core remains the reference geometry, but it
is not assumed to fit this much larger full-PREP netlist.  Mapped area and
placement-capacity checks must be completed before the canonical launch.  If
an enlarged floorplan is required, one value is frozen for both variants
before either physical job runs; neither variant may receive private tuning.

## Effective seed contract

The predefined primary seed is `1` for GPL, GRT and DRT.  There is no seed
sweep and no best-seed selection.

Pinned-source inspection gives the following exact DRT semantics:

- ORFS commit `0c914a...`, `flow/scripts/detail_route.tcl`, passes `OR_SEED`
  and `OR_K` only when the environment variables are nonempty;
- its OpenROAD submodule is commit
  `0b54bb3203e0895f87940ff982358a6e4d406e28`;
- `src/drt/src/TritonRoute.tcl` defaults `or_seed=-1` and `or_k=0`;
- `src/drt/src/dr/FlexDR_maze.cpp`,
  `FlexDRWorker::mazeIterInit_sortRerouteNets`, computes
  `numSwap = rerouteNets.size() * OR_K` and performs that many seeded adjacent
  swaps only for maze iteration zero.

The new checkpoint sets `GPL_RANDOM_SEED=1`, `GRT_SEED=1`, `OR_SEED=1` and
`OR_K=1.0`.  Thus DRT performs one seeded adjacent-swap attempt per reroute-net
entry (subject to integer conversion) without adding routing iterations.  The
actual `detailed_route` command must be captured and must contain both
`-or_seed 1` and `-or_k 1.0`.  This is a single seeded implementation pair,
not evidence of seed robustness.

## Pre-physical gates

Before physical launch:

1. verify the production RTL byte manifest;
2. regenerate and hash all four ROM files;
3. compile/simulate both parameter values;
4. check `D=2^63`, `D=2^64-1`, `X=0`, `X=D-1`, PREP corrections 0..4,
   `D=9232379236109516801` and `D=9340465626629537792`;
5. check selected `r` and `NX` against exact integer arithmetic;
6. check V36/V43 registered outputs for equivalence on legal vectors;
7. map both variants with the identical single-ABC flow;
8. verify 160 mapped data flops, no residual memories and complete mapped
   reports;
9. freeze one common floorplan after the mapped capacity check.

## Result statuses and strict pass

Each row reports three independent statuses: Actions job conclusion,
measurement validity, and strict physical pass/fail.  Strict pass requires all
of:

- setup slack >= 0 and setup TNS = 0;
- hold slack >= 0 and hold TNS = 0;
- zero max-capacitance, max-transition and max-fanout violations;
- zero detailed-route DRC and antenna violations;
- nonempty final ODB, DEF, GDS, Verilog, SDC and SPEF.

The criterion is frozen before results and will not be weakened.  With
`LEC_CHECK=0`, timing, geometry and extracted-RC measurements remain valid,
but post-physical logical equivalence remains an open gate unless separate
reproducible evidence is obtained.

## Prohibited interpretation

The canonical comparison is only V36 PREP5 full PREP versus V43 PREP5 full
PREP under this single declared contract.  Historical isolated PREP6 results
may be context but are not subtracted as an architecture effect.  The result
does not establish complete-divider Fmax, CPU latency, PVT robustness, power,
energy, silicon area, universal V43 superiority or seed robustness.  No
`g_L`, V45/V46, FINAL change or arithmetic optimization is part of this stage.
